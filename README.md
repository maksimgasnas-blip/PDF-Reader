# PDF Студия — нативный редактор и читатель PDF для Windows

Один файл — `release/PDF-Studio.exe`, **26 МБ** (вместе с встроенным OCR и четырьмя
семействами шрифтов, UPX), никакой
установки, никаких зависимостей, никакого интернета. Написан на C (Win32 API) поверх
движка **MuPDF**, статически слинкован: внутри нет ни Electron, ни браузера,
ни .NET, ни Java.

Из коробки: **назначает себя программой для PDF** (двойной щелчок по файлу открывает
редактор) и умеет показывать **несколько страниц сразу** — две в ряд, сетку 3×N или
непрерывную ленту с прокруткой.

Оформление — **Windows XP (тема Luna)**: синий заголовок с кнопками окна,
строка меню, панель инструментов со значками, линейка, боковая панель инструментов
и строка состояния с ползунком масштаба. Всё нарисовано вручную на GDI и через
двойную буферизацию: при движении курсора и наведении на кнопки **ничего не мерцает**.
Вид не зависит от версии Windows — на XP, 7, 10 и 11 окно выглядит одинаково.

| Что | Значение |
|---|---|
| Файл | `release/PDF-Studio.exe` (26 МБ, UPX) — правка текста, OCR, таблицы, картинки, шрифты и весь интерфейс внутри |
| Системы | Windows **XP SP3 – 11**, и 32-, и 64-битные (единый x86-бинарник) |
| Зависимости | только системные DLL: `kernel32`, `user32`, `gdi32`, `comdlg32`, `shell32`, `msvcrt` (ни `comctl32`, ни `.NET`, ни VC-runtime не нужны) |
| Установка | не нужна: скопировал и запустил, в том числе с флешки |
| Сеть | не используется вообще |

**Новое в этой сборке (раунд 9):** таблицы (`Ctrl+T`, `Tab` по ячейкам),
вставка своих картинок (`Ctrl+M`, PNG/JPEG/BMP), выбор гарнитуры
(Times New Roman / Arial / Courier New / Arial Narrow — встроены в exe),
кнопки «+ строка / + столбец / удалить таблицу». Снимки интерфейса:
`screenshot.png` (режим документа с таблицей и картинкой), `screenshot-edit.png`.

Почему именно так: раньше была веб-версия и Electron-сборка (82 МБ, требовала
Windows 7+ и тянула за собой Chromium). Они удалены. Нативный вариант запускается
на машинах, где нет ничего свежее Windows XP, и весит вчетверо меньше.

## Что умеет

**Чтение**
- рендер страниц через MuPDF (векторный, со шрифтами, без «мыла»);
- масштаб: `+` / `−` / по ширине (`0`), Ctrl+колесо мыши;
- **несколько страниц на экране** (меню «Вид» или кнопки на панели):
  «Одна страница», «Непрерывно» (все страницы лентой с прокруткой), «Две страницы»
  в ряд, «Несколько страниц» (сетка 2–3 колонки, выбирается по ширине окна);
  масштаб при переключении подбирается так, чтобы страницы влезли целиком;
  видимые страницы кэшируются (до 8 штук), поэтому прокрутка не перерисовывает MuPDF;
- навигация: `PgUp`/`PgDn`, кнопки «◀ ▶» на панели инструментов, прыжок на страницу
  вводом номера в поле на панели (Enter), счётчик «Стр. N из M» в строке состояния;
  клик по любой странице в многоколоночном виде делает её текущей (в неё же попадают
  пометки и правки текста);
- выделение текста мышью с подсветкой и **копированием в буфер обмена** (инструмент «Выбор»);
- поиск по странице (`Ctrl+F`, далее `F3`): найденные вхождения подсвечиваются,
  текущее — оранжевым, остальные — рамками; в статусе «Найдено на странице 1: 5»;
- «Копировать текст» (вся страница) на боковой панели инструментов;
- открытие файла из проводника (перетаскиванием в окно), из командной строки,
  через `Ctrl+O` и обычный диалог;
- **режим документа** — полноценный текстовый процессор: текст течёт по страницам
  как в Word, оформляется (полужирный, курсив, подчёркивание, кегль, цвет,
  выравнивание, списки, интервалы, красная строка, колонтитулы, номера страниц,
  размер страницы и поля) и сохраняется в новый PDF (см. отдельный раздел).

**Редактирование (правки сохраняются в PDF как стандартные аннотации)**
| Инструмент | Что делает |
|---|---|
| Выбор | выделение и копирование текста; клик по полю формы — заполнение |
| Текст | вставляет текстовое поле (FreeText) поверх страницы |
| Маркер | выделение текста жёлтым (Highlight с QuadPoints) |
| Рамка | прямоугольник (Square) |
| Заметка | иконка-примечание с текстом (Text + Popup) |
| Перо | рисунок от руки (Ink, ломаная по движениям мыши) |
| Ластик | удаляет правку, лежащую под курсором |

Правки видны в любом другом просмотрщике (Adobe Reader, Foxit, браузер), потому что
это штатные объекты PDF, а не «нарисованные поверх» картинки.

**Страницы** (меню «Документ»)
- повернуть страницу влево / вправо (`Ctrl+R`, `Ctrl+Shift+R`);
- дублировать (`Ctrl+D`), удалить (с подтверждением), переместить выше / ниже.

**Формы**
- клик по полю в режиме «Выбор» — ввод значения (текстовые поля, списки);
- флажки и переключатели переключаются кликом;
- значения сохраняются в PDF (`/V`), поля только для чтения не трогаются.

**Прочее**
- печать (`Ctrl+P`) через системный диалог печати, все страницы с учётом поворотов;
- документы под паролем: при открытии спрашивается пароль;
- сохранение (`Ctrl+S`) атомарное: пишется `.tmp`, затем подменяется — исходный файл
  не портится, если запись не удалась; «Сохранить как…» — в новый файл;
- строка состояния, счётчик страниц, защита от потери несохранённых правок при выходе.

## Правка текста «как в Word» и OCR сканов

**Правка текста** (меню «Инструменты → Правка текста», клавиша `F2` или `Q`)

- клик по строке текста — блок выделяется, появляется каретка; можно печатать;
- `Backspace` / `Delete`, `Enter` (новая строка), `←` `→` `↑` `↓`, `Home`/`End`,
  `Ctrl+Home`/`Ctrl+End`, выделение мышью или `Shift`+стрелки, `Ctrl+A`, `Ctrl+Z`;
- **перевёрстка как в Word**: пока набираете, текст переносится по ширине блока,
  последующие строки блока сдвигаются;
- `Esc` фиксирует правку, `Ctrl+S` записывает файл;
- **под правкой настоящий фон страницы, а не «заплатка»**: страница рендерится
  второй раз без текстового слоя (своё устройство-фильтр MuPDF: текст глушится,
  графика, изображения, градиенты и заливки остаются), и в предпросмотре из этого
  рендера просто копируется участок под блоком. Поэтому правка одинаково
  бесшовно ложится на однотонный лист, на красно-синий разворот, на плашку и на
  фото/градиент — ни белых, ни цветных прямоугольников не появляется;
- блок для правки выбирается по «содержательности» (больше всего символов под
  курсором), поэтому клик по строке не попадает в пустой блок-огрызок или маркер
  списка.

Скриншот правки на тёмном фоне: `screenshot-edit.png`.

### Правка текста не должна менять шрифт и ломать режим документа (исправлено)

Что было не так и что сделано:

- **был баг: после клика «Изменить текст» шрифт менялся** на Noto Sans и кегль
  поджимался до 72 %, чтобы текст влез в ширину блока. Теперь берётся стандартный
  шрифт того же семейства и начертания, что и в исходнике, кегль сохраняется,
  строки переносятся по тем же местам (допуск 0.6 pt на разницу метрик);
- **был баг: в режиме документа абзацы разъезжались, накладывались друг на друга
  и закрывались белыми прямоугольниками**. Причина: в режиме документа поверх
  перевёрстанного текста продолжали рисоваться наложения правки из режима страниц
  (вместе с их «закраской» фона). Теперь в режиме документа наложения не рисуются,
  а несохранённые правки перед сборкой документа запекаются в PDF — текст правки
  входит в перевёрстку нормально;
- **«видна только первая страница и кусок второй»**: это не обрезка. Режим
  документа переверстывает текст подряд, поэтому 5 разреженных страниц исходника
  превращаются в 2 плотные; `Ctrl+End` доводит до последнего абзаца (проверено —
  виден заголовок «Page 5 of 5» и конец текста). Счётчик страниц и число символов
  показаны в строке состояния;
- известное ограничение: узкая боковая колонка исходника (если она есть) попадает
  в перевёрстку отдельным абзацем сразу после своего абзаца — это не потеря
  текста, а упрощение модели «одна колонка».

Проверка (тестовый файл `tests/gen_sample.py`, 5 страниц A4, Times 8 pt,
боковая колонка):

- `--selftest sample5.pdf out.pdf 150 125 " TEST"` → в `pdftotext -layout` строки
  совпадают с исходными посимвольно, «TEST» дописан в конец последней строки
  блока, кегль и разбивка строк не изменились;
- в GUI: клик по абзацу → шрифт остаётся Times, разбивка строк та же; `Esc`,
  затем `Ctrl+Shift+D` → чистый документ без наложений, правка в тексте
  (7095 символов против 7090 до правки), `Ctrl+End` доходит до конца.

Что происходит при сохранении (честная механика, без «картинок поверх»):

1. старый текст в прямоугольнике блока вырезается настоящей **redaction**
   (`/Redact`, текст удаляется из потока содержимого, не закрашивается —
   подложка под ним, какого бы цвета она ни была, остаётся нетронутой);
2. новый текст пишется тем же кеглем, цветом и **тем же семейством шрифта**
   (Times-Roman / Helvetica / Courier — стандартные шрифты PDF, кириллица —
   встроенный Noto Sans) с корректным `/ToUnicode`. Кегль больше не поджимается
   под ширину блока (раньше из-за этого абзац после правки выглядел мельче и
   «другим шрифтом»);
3. в результате текст остаётся **настоящим текстом**: он ищется `Ctrl+F`, копируется,
   извлекается любым парсером (`pdftotext`, `pypdf`), а не превращается в изображение.

**OCR сканов** (меню «Инструменты» → «Распознать страницу» / «Распознать весь документ»)

- встроенный **tesseract** (внутри exe, модели `rus`+`eng` вшиты как ресурсы,
  при первом запуске распаковываются в `%TEMP%\PDFStudioOCR`);
- распознанный текст ложится на страницу **невидимым текстовым слоем**: картинка
  остаётся как была, но по ней работает поиск, копирование и правка;
- скорость на тестовом скане A4 (1240×1754): **0,4–0,7 с на страницу**, ~370 символов;
- интернет не нужен, ключи API не нужны, всё локально.

Демонстрационные файлы: `examples/wrap-test.pdf` (узкий Times — проверка, что правка
не ломает вёрстку соседних строк), `examples/contract.pdf` (чистый текст — удобно править),
`examples/demo.pdf` (4 страницы: текст, форма, поиск), `examples/dark-page.pdf`
(тёмный титульный лист + белая плашка с текстом), `examples/colored-bg.pdf`
(красно-синий разворот — строка на границе цветов), `examples/gradient-bg.pdf`
(фото-градиент, тёмное пятно и жёлтая полоса), скан — любой PDF-скан.

## Режим документа: полноценный текстовый процессор

Меню **«Вид → Режим документа (текст как в Word)»**, горячие клавиши `Ctrl+Shift+D`.
Галочка в меню показывает, что режим включён. Когда режим включён, под панелью
инструментов появляется **вторая полоса — панель форматирования**.

Это второй, «книжный» способ работы с PDF. Обычная правка (инструмент «Правка
текста») двигает только строки внутри блока PDF — так устроен любой PDF. Режим
документа делает то, что делает Word: **пересобирает страницы из абзацев**, а
текст в них можно оформлять.

### Что можно делать с текстом

| Действие | Кнопка на панели | Клавиши |
|---|---|---|
| Полужирный / курсив / подчёркнутый | `Ж` `К` `Ч` | `Ctrl+B` `Ctrl+I` `Ctrl+U` |
| Кегль (шрифт текста) | `A−` `A+`, текущий кегль в окошке | — |
| **Гарнитура (семейство шрифта)** | кнопка «Times» → выпадающий список | — |
| Цвет текста | шесть образцов цвета | — |
| Выравнивание: слева / по центру / справа / по ширине | `Л` `Ц` `П` `Ш` | `Ctrl+L` `Ctrl+E` `Ctrl+R` `Ctrl+J` |
| Маркированный / нумерованный список | `•` `1.` | `Ctrl+Shift+L` / `Ctrl+Shift+M` |
| Межстрочный интервал 1,0 → 1,15 → 1,5 → 2,0 | кнопка с числом | — |
| Красная строка | `→` `←` | — |
| Отменить / повторить (40 шагов) | `Отмена` `Повтор` | `Ctrl+Z` `Ctrl+Y` |
| Верхний и нижний колонтитулы | «Формат → Колонтитулы…» | — |
| Номера страниц | «Формат → Номера страниц» (галочка) | — |
| Размер страницы A4 / A5 / Letter, книжная / альбомная, поля в мм | меню «Формат» | — |
| **Вставить таблицу 3×3** | «Вставка → Таблица» | `Ctrl+T` |
| **Добавить строку / столбец, удалить таблицу** | «Вставка → Таблица: …» | — |
| **Вставить свою картинку** (PNG/JPG/BMP из файла) | «Вставка → Картинка…» | `Ctrl+M` |
| Переход по ячейкам таблицы | — | `Tab` / `Shift+Tab`, `Enter` — новая строка |
| Найти и заменить | поле «Найти» + «Правка → Найти и заменить…» | `Ctrl+F` `Ctrl+H` / `F3` |
| Вырезать, копировать, вставить | «Правка» | `Ctrl+X` `Ctrl+C` `Ctrl+V` |

Формат применяется к **выделению**; если ничего не выделено — к **слову под
кареткой** (так же ведёт себя Word) либо запоминается для дальнейшего набора.
Свойства абзаца (выравнивание, список, интервал, красная строка) применяются ко
всем абзацам выделения.

### Таблицы, свои картинки и выбор шрифта (раунд 9)

**Таблицы.** `Ctrl+T` (или «Вставка → Таблица») вставляет таблицу 3×3 в то место,
где стоит каретка. Ячейка — это обычный абзац со своей рамкой, поэтому внутри
работает всё оформление: `Ж` `К` `Ч`, кегль, цвет, выравнивание. `Tab` переводит
каретку в следующую ячейку, в последней ячейке `Tab` (`Enter`) добавляет новую
строку. «Вставка → Таблица: + строка / + столбец / удалить таблицу» меняет
структуру — до 40 строк и 10 столбцов, ширина столбцов делится поровну по полю
набора. В сохранённом PDF рамки таблицы рисуются настоящими линиями, текст в
ячейках остаётся текстом (его видно поиском и `pdftotext`).

**Свои картинки.** `Ctrl+M` (или «Вставка → Картинка…») открывает обычный диалог
выбора файла и вставляет PNG / JPEG / BMP под курсор как отдельный абзац потока:
картинка занимает страницу по ширине, текст перетекает ниже, при вставке внутри
таблицы картинка ставится после таблицы — сетка не рвётся. В PDF картинка
записывается как изображение (не как рисунок поверх), цвета и ориентация
совпадают с исходным файлом.

**Шрифт.** Кнопка с названием гарнитуры на полосе форматирования («Times»)
открывает список: **Times New Roman, Arial, Courier New, Arial Narrow** (узкий).
В программу встроены свободные метрические аналоги Liberation (Serif, Sans, Mono,
Sans Narrow), поэтому выбор работает **без установленных шрифтов в системе** и на
Windows XP тоже. В сохранённый PDF попадают именно эти TrueType-шрифты (подмножества,
`pdffonts` показывает Times New Roman / Arial / Courier New), текст остаётся
извлекаемым.

### Как это работает

1. PDF разбирается на строки (`fz_stext`), строки склеиваются в **абзацы**;
   **каждый символ** получает свой стиль — кегль, цвет, полужирный, курсив
   (в абзаце до 24 разных стилей). Двойные пробелы, мягкие переносы и служебные
   знаки из старых шрифтов вычищаются, слова, разорванные переносом, склеиваются;
   картинки (кроме полноразмерных сканов) переносятся в поток как объекты;
2. абзацы **верстаются заново**: перенос по словам, поля, выравнивание по ширине
   (с растяжкой пробелов), межстрочный интервал, отступы, разрывы страниц —
   всё считается программой;
3. правка идёт как в текстовом редакторе: каретка ставится кликом в любое место,
   `Enter` — новый абзац, `Backspace` в начале абзаца — склейка с предыдущим,
   `← → ↑ ↓ Home End Ctrl+← Ctrl+→ Ctrl+Home Ctrl+End`, `Shift`+стрелки и мышь —
   выделение, `Ctrl+A`, `Ctrl+C/X/V` (русский текст вставляется из буфера);
4. **набранное перетекает по странице**: строки ниже сдвигаются, а когда текст
   упирается в нижнее поле — автоматически появляется новая страница
   (счётчик «Стр. N из M» растёт). Удалили текст — лишние страницы исчезают;
5. `Ctrl+S` собирает **новый PDF** из потока: тот же шрифт (Noto Sans), тот же
   кегль, цвет, начертание и выравнивание, что на экране; предлагается имя
   «<имя> (документ).pdf», чтобы исходник остался целым. Полужирный пишется как
   контурная обводка текста, подчёркивание — линией, списки — маркером и номером,
   колонтитулы и номер страницы — на каждой странице;
6. экран и сохранённый PDF совпадают: шрифт Noto Sans регистрируется в GDI из
   встроенных данных MuPDF, поэтому ширины букв на экране те же, что в файле;
7. печать (`Ctrl+P`) в этом режиме печатает перевёрстанный документ.

### Ограничения режима (осознанные)

- гарнитур четыре (Times New Roman, Arial, Courier New, Arial Narrow) — своего
  TTF-файла с диска программа пока не подхватывает;
- **таблица и картинка живут в потоке, а не в формате PDF**: в сохранённом файле
  они записаны графикой (рамки — линии, картинка — изображение), обратно в
  структуру при открытии файла они не читаются. То есть PDF «как на экране»
  выглядит правильно, но если открыть его снова и войти в режим документа,
  таблица распадётся на абзацы, а картинка в поток не попадёт (в режиме страниц
  файл отображается полностью и правильно);
- таблица из исходного PDF (нарисованная линиями) в поток не превращается —
  вытягивается в обычные абзацы, как и раньше; своя таблица вставляется через
  `Ctrl+T`;
- ячейки нельзя объединять, в ячейку нельзя вложить картинку, ширина столбцов
  пока не тянется мышью;
- одна колонка: многоколоночные вёрстки вытягиваются в один поток;
- векторная графика исходника (линейки, рамки) в поток не переносится;
- если в PDF нет текстового слоя (скан) — сначала «Инструменты → Распознать
  страницу», потом режим документа.

## Исправлено после проверки

- **режим документа** добавлен (см. выше) — плюс по ходу исправлено: панель
  режима не перерисовывалась целиком, вёрстка не считалась до первой отрисовки,
  `Enter`/`Backspace` могли уронить редактор при склейке абзацев, после отмены
  оставалось «фантомное» выделение, статус не обновлял счётчики, а сохранение
  под русским именем файла не работало (MuPDF/CRT не открывает такие имена —
  теперь запись идёт напрямую, а при отказе через временный файл и Win32-перенос);

- **Кнопка «Открыть» на пустом окне.** Раньше все кнопки панели были неактивны,
  пока не открыт документ — включая «Открыть». Теперь «Открыть», «Выход»,
  «О программе» и переключатель панели инструментов доступны всегда.
- **Разворот окна накрывал панель задач.** Окно рисует свой заголовок (WS_POPUP),
  и при развороте уходило на весь экран целиком. Теперь размер развёрнутого окна
  ограничен рабочей областью (`WM_GETMINMAXINFO` + `SPI_GETWORKAREA`), панель
  задач Windows остаётся видимой и доступной.
- **Мерцание при выделении маркером.** Окно страницы рисовалось прямо на экране:
  сначала серый фон, потом страница. Теперь вся отрисовка идёт в память и
  показывается одним `BitBlt`, перерисовка без стирания фона — при перетаскивании
  рамки выделения и при прокрутке ничего не мигает.
- **Подсказки над меню.** Над пунктами «Файл», «Правка», «Вид» и т. д. всплывала
  подсказка; теперь над строкой меню подсказок нет вообще, а пока меню открыто,
  подсказки скрываются.
- **Поиск не прокручивал к найденному.** Вхождения подсвечивались, но за
  пределами экрана их не было видно. Теперь после `Enter`, `F3` и «Найти далее»
  вид автоматически прокручивается так, чтобы текущее вхождение было на экране.
- **Иконки.** Раньше 16-пиксельная графика растягивалась в 20 пикселей — отсюда
  «кривые» края. Теперь каждая иконка рисуется вчетверо крупнее в 32-битном DIB и
  уменьшается `StretchBlt`-ом в режиме HALFTONE: GDI усредняет пиксели, получается
  сглаженная картинка. Заодно перерисованы папка, дискета, принтер, маркер и
  «страница с карандашом».
- **Правка ломала вёрстку (главное).** Шрифт, которым пишется новый текст, шире
  исходного (Times/Arial), поэтому каждая строка становилась шире блока и
  последнее слово «уезжало» на новую строку — текст после правки разваливался на
  рваные строки. Теперь кегль блока автоматически подбирается так, чтобы самые
  широкие исходные строки уложились в ширину блока (`pdfdoc_fit_size`), а переводы
  строк перестали попадать в текст (раньше на конце строк появлялся «квадратик»
  отсутствующего глифа). Строки после правки остаются на своих местах.
- **Сохранение поверх занятого файла.** Если файл открыт другой копией программы,
  теперь остаётся `.tmp`-копия и она сразу открывается, а не теряется правка;
  остатки прошлой неудачной записи удаляются перед сохранением.

## Программа по умолчанию для PDF

- при **первом запуске** программа спрашивает: «Сделать PDF Студию программой для
  открытия PDF-файлов?» — по «Да» прописывается сама, без прав администратора
  (всё в `HKEY_CURRENT_USER\Software\Classes`, работает и на XP, и на 11);
- то же самое в любой момент: меню **«Справка → Сделать программой по умолчанию»**;
- что записывается: ProgID `PDFStudio.Document` (команда `"путь\PDF-Studio.exe" "%1"`,
  своя иконка), расширение `.pdf`, `OpenWithProgids` и `OpenWithList`,
  запись `Applications\PDF-Studio.exe` с `SupportedTypes`, плюс
  `HKCU\Software\RegisteredApplications` → `…\Capabilities` для списка
  «Программы по умолчанию»; затем `SHChangeNotify(SHCNE_ASSOCCHANGED)`;
- на Vista/7 дополнительно вызывается официальный
  `IApplicationAssociationRegistration::SetAppAsDefault`; на XP этого объекта нет —
  остаётся запись в реестре, которую XP понимает;
- если exe перенесли в другую папку, при следующем запуске путь в реестре
  обновляется автоматически (ярлыки не отваливаются);
- Windows 8–11 хранит выбор пользователя в защищённом ключе `UserChoice`, который
  программа менять не имеет права. Поэтому на «восьмёрке» и новее система может
  один раз спросить подтверждение: свойства PDF → «Открыть с помощью» →
  «Выбрать программу» → PDF Студия → «Использовать всегда».

## Чего пока нет (честно)

- обычная правка текста (инструмент «Правка текста») работает по блокам разметки
  PDF: сдвигаются только строки внутри блока, остальная страница стоит на месте.
  Для «настоящего» перетекания служит режим документа — но он пересобирает
  страницу целиком и теряет исходное оформление (см. ограничения выше);
- в режиме документа одна колонка: многоколоночные вёрстки вытягиваются в один поток;
- **таблиц нет**: таблица из PDF превращается в обычные абзацы, создать новую
  таблицу в режиме документа нельзя;
- **вставить свою картинку в документ нельзя** (переносятся только те, что уже
  были в PDF);
- гарнитуру выбрать нельзя — один встроенный шрифт Noto Sans (кегль, цвет,
  полужирный, курсив, подчёркивание — можно);
- после правки шрифт заменяется на встроенный Noto Sans (исходный гарнитурный файл
  не переиспользуется): кегль, цвет и положение сохраняются, рисунок букв — нет;
- OCR рассчитан на печатный текст (rus+eng); рукописный и таблицы с линиями
  распознаются плохо, как и у любого tesseract без дообучения;
- нет штампов, подписей и вложений;
- нет перестановки страниц перетаскиванием (только кнопками «выше/ниже»);
- нет создания PDF «с нуля» и объединения нескольких файлов;
- выделение текста — прямоугольником, а не «от символа к символу»;
- нет вкладок/нескольких документов в одном окне (один файл — одно окно);
- нет панели миниатюр и закладок (в многоколоночном виде их роль играет сетка страниц);
- в сетке страницы разного формата (например, повёрнутые) выравниваются по первой
  странице и обрезаются по своей ячейке.

## Сборка из исходников

Нужны: Linux (или MSYS2), `mingw-w64` (i686), `make`, ~4 ГБ swap при сборке движка.

```bash
cd native
./fetch-mupdf.sh              # 1) скачает MuPDF 1.24.9, применит патч и соберёт
                              #    libmupdf.a / libmupdf-third.a под mingw32
MUPDF=/tmp/mupdf/mupdf-1.24.9-source ./build.sh   # 2) соберёт приложение
```

Проверка без GUI (диагностические ключи, в обычной работе не нужны):

```bash
# режим документа: собрать поток из PDF, вставить текст, сохранить перевёрстанный PDF
#   --flowtest in.pdf out.pdf x y "текст"      (@файл — текст из UTF-8 файла)
# оформление: жирный+подчёркнутый+курсив, центр/по ширине, список, интервал, цвет,
# номер страницы — и сохранение (проверка модели форматирования и записи):
#   --fmttest in.pdf out.pdf
# правка текста: открыть, дописать строку в блок под точкой (167,122), сохранить
wine release/PDF-Studio.exe --selftest in.pdf out.pdf 167 122 " ДОПОЛНЕНИЕ"
pdftotext out.pdf - | head        # в тексте появится «ДОПОЛНЕНИЕ»

# OCR: распознать страницу 1 и сохранить с текстовым слоем
wine release/PDF-Studio.exe --selfocr in.pdf out.pdf

# снимок интерфейса без графической оболочки (проверка вида):
#   --shot out.bmp [файл.pdf] [страница 0..] [боковая панель 0/1]
wine release/PDF-Studio.exe --shot out.bmp examples/demo.pdf 0 1
convert out.bmp shot.png
./build.sh                    #    (если библиотеки уже лежат в /tmp/mupdf — хватит этого)
NOUPX=1 ./build.sh            #    несжатый exe (~53 МБ) вместо UPX
```

`fetch-mupdf.sh` сам скачивает архив, патчит `source/fitz/directory.c`
(`_wstat` → `_wstat64`, иначе свежие mingw-w64 не собирают MuPDF) и запускает
`make OS=mingw32-cross build=release libs USE_TESSERACT=no -j2`.
При 2 ГБ ОЗУ нужен swap на 3–4 ГБ, иначе сборка harfbuzz падает по памяти.

> Каталог `release/` выбран специально: каталоги с именами `dist`, `build`, `out`,
> `node_modules`, `target`, `coverage` и т.п. **не попадают в снапшот воркспейса**,
> поэтому готовый exe в них «исчезает» при переносе проекта.

`build.sh` делает: `windres` для иконки и VERSIONINFO → `i686-w64-mingw32-gcc -O2 -s
-municode -mwindows -D_WIN32_WINNT=0x0501 -static` → статическая линковка с
`libmupdf.a`, `libmupdf-third.a`, `libstdc++` → UPX.

Исходники приложения:
- `native/src/main.c` — приложение: окно, страница, инструменты, печать, диалоги;
- `native/src/wui.c` / `wui.h` — слой оформления Windows XP (заголовок, меню,
  панель инструментов, линейка, строка состояния, боковая панель, подсказки,
  36 векторных значков, offscreen-отрисовка);
- `native/src/cmds.h` — общие идентификаторы команд и инструментов;
- `native/src/pdfdoc.c` / `pdfdoc.h` — обёртка над MuPDF (рендер, поиск, аннотации,
  страницы, формы, текст);
- `native/src/pdftext.c` — текстовые блоки и «запекание» правки в поток страницы;
- `native/src/textedit.c` / `textedit.h` — модель правки текста (каретка, выделение,
  переносы, отмена);
- `native/src/app.rc` — иконка и версия ресурсов;
- `native/fetch-mupdf.sh` — загрузка и сборка движка одной командой.

### Совместимость с XP
- `_WIN32_WINNT=0x0501`, `WINVER=0x0501`;
- не используются API новее XP (проверено по таблице импортов: ни `GetTickCount64`,
  ни `InitializeCriticalSectionEx`, ни SRW-locks и т.п.);
- `SetProcessDPIAware` вызывается через `GetProcAddress` (на XP его просто нет);
- используется `SetWindowLongW`/`GetWindowLongW`, `wvsprintfW`, `wsprintfW`;
- x86-бинарник одинаково работает в 32- и 64-битной Windows.

## Как это проверялось

**Раунд 9 (таблицы, картинки, шрифты), факты и чем проверено:**

- `--tbltest` (встроенный тест: открыть PDF → режим документа → `Ctrl+T` →
  текст в три ячейки → `+ строка` → `+ столбец` → шрифт Arial на всё выделение и
  Courier для новых символов → сохранить): лог
  `tbltest: insert=1 в_таблице=1 / row_add=1 col_add=1 / стр=2 абз=51 симв=7096 /
  export rc=0`. В результате `pdftotext -layout` показывает `A1 B1 C1` и текст
  ячеек в колонках, `pdffonts` — **Arial CID TrueType Identity-H (встроен)** и
  **Courier New**, то есть в файл попали разные гарнитуры, а не один Noto.
- Живой прогон в wine (Xvfb, xdotool): `Ctrl+Shift+D` → `Ctrl+T` → ввод латиницей
  `Quarter`/`Plan`/`Fact` по `Tab` → `Ctrl+M` → PNG → `Ctrl+S` → файл 441 851 Б;
  `pdftotext -layout` и рендер `pdftoppm` подтверждают: сетка 3×3 линиями, текст в
  ячейках, картинка 320×200 RGB не перевёрнута, цвета совпадают с исходником.
- Диалог шрифта: клик по кнопке «Times» на полосе форматирования открывает список
  `Times / Arial / Courier / Узкий` с галочкой на текущем.
- Найденные и исправленные по ходу баги: `Tab` вставлял символ табуляции вместо
  перехода по ячейкам; текст в ячейке наследовал кегль заголовка (18 pt bold) —
  теперь в ячейке 11 pt, обычное начертание; вставка картинки при курсоре в таблице
  рвала сетку (картинка ставится после таблицы); картинка в PDF была перевёрнута
  по вертикали; цвета были инвертированы (лишняя перестановка каналов BGR);
  после вставки картинки в пустых ячейках оставались синие полосы (выделение не
  снималось).
- Сборка: `NOUPX=1 MUPDF=/opt/mupdf-src sh native/build.sh`, затем
  `upx --best --lzma` → 26 161 664 Б, MD5 `281f39a59ed6fdb927de79d7eab8b828`;
  упакованный exe прогнан тем же `--tbltest` и в GUI — работает, шрифты
  извлекаются из ресурсов.

Тесты прогонялись в wine (режим Windows 10 и отдельно **режим Windows XP**),
кадры снимались через Xvfb + ImageMagick, действия — xdotool; результат проверялся
независимым парсером PDF (pypdf), а не только «на глаз»:

- открытие файла из командной строки, навигация, рендер 4-страничного демо;
- маркер, рамка, перо, заметка, текст → после `Ctrl+S` в файле появились
  `/Highlight` с `/QuadPoints`, `/Square`, `/Ink` с `/InkList`, `/Text` + `/Popup`,
  `/FreeText` с ожидаемыми координатами и цветами;
- заполнение формы: клик по полю, ввод → `/V` поля изменился
  (`fullName: Sidorov Sidor`), остальные поля не тронуты;
- поворот страницы → `/Rotate 90` в файле; дублирование → 5 страниц;
  удаление → снова 4; «страницу выше» → порядок страниц изменился;
- выделение текста мышью → в буфере обмена оказался выделенный фрагмент
  (проверено вставкой в поле поиска), в статусе «Скопировано в буфер обмена: 96 симв.»;
- поиск «PDF» → «Найдено на странице 1: 5», вхождения подсвечены;
- печать и диалог пароля — открываются (принтера в песочнице нет, печать до конца
  не проверялась);
- режим документа: `--flowtest` собирает поток из `contract.pdf` (6 абзацев,
  379 символов), вставляет текст и сохраняет PDF — текст на месте, страницы
  пересчитываются; вставка 20 000 символов в `wrap-test.pdf` даёт 2 страницы
  вместо одной (проверено `pdfinfo`/`pdftotext` и рендером `pdftoppm`);
- в GUI (wine): меню «Вид → Режим документа», клик в середину абзаца, набор
  латиницы и вставка русского текста из буфера — абзац переверстался, каретка
  на месте, счётчик страниц вырос с 1 до 4 после вставки большого текста;
  `Ctrl+Z`, `Enter`, `Backspace` — без падений; `Ctrl+S` пишет
  «Договор поставки (документ).pdf», `pdftotext` показывает вставленный текст,
  экран и файл совпадают; проверено и сохранение под русским именем файла;
- форматирование (финальная сборка): `--fmttest` на `contract.pdf` — выделить всё,
  полужирный + подчёркнутый + по центру + по ширине + маркированный список +
  межстрочный 1,15 + красный цвет + номер страницы → `flow_fmt_get` подтверждает
  `bold=1 und=1 align=3 list=1 sp=1.15 color=C00000`, экспорт даёт PDF, в потоках
  которого есть `.7529412 0 0 rg` (красный), обводка `1 Tr` (полужирный) и линия
  подчёркивания;
- в GUI (wine + Xvfb): панель форматирования появляется и исчезает вместе с режимом;
  `Ц` центрирует абзацы, `Ж` делает выделение полужирным, `•` и `1.` ставят списки
  (маркеры рисуются и на экране, и в PDF), образец цвета перекрашивает выделение
  (проверено по пикселям кадра: `#C20909` в заголовке), `Л/Ц/П/Ш` переключают
  выравнивание, `Отмена`/`Повтор` откатывают и возвращают правку;
  `Ctrl+Shift+D` включает режим из любого места окна; `Ctrl+M` со списком больше не
  вставляет лишний перевод строки (Ctrl-сочетания гасят символ);
  `Ctrl+H` → «Заменить на» → «Заменено вхождений: 3» с сохранением начертания;
  нижний колонтитул + номера страниц попали в сохранённый PDF
  (`pdftotext`: «Договор поставки, черновик 1»); `pdffonts` — один встроенный
  Noto Sans, текст извлекается.

Файлы для проверки: `examples/demo.pdf` (титул, форма, повёрнутая страница, смета),
`examples/contract.pdf` (чистый текстовый договор — для правки и OCR),
`examples/demo-locked.pdf` (под паролем), `examples/demo-annotated.pdf` (пример правок),
`test-out/scan.pdf` — «скан» счёта для OCR.

Правка текста и OCR проверены отдельно, на финальной сборке:

- `--selftest` на `examples/contract.pdf`: блок под точкой (167,122) прочитан,
  дописан текст, правка запечена и сохранена → `pdftotext` показывает строку
  с дописанным текстом, кириллица («Настоящий договор заключён…») сохранилась;
- рендер результата (poppler) совпадает с исходной вёрсткой: старые буквы вырезаны,
  новые стоят на тех же базовых линиях, перенос по ширине блока работает;
- `--selfocr` на `test-out/scan.pdf`: 372 символа за 0,7 с, в результате
  `pdftotext` читает «СЧЁТ НА ОПЛАТУ», «Поставщик: ООО «Ромашка», г. Краснодар»;
- в GUI (wine + Xvfb) проверена вся оболочка: открытие всех шести меню, полные
  подписи и ускорители в выпадающих списках, закрытие по `Esc` и кликом мимо,
  включение боковой панели из меню «Вид» и левой рейки, кнопки панели инструментов
  (масштаб, «по ширине», «100 %»), подсказки при наведении, перевод страницы
  (ввод номера + Enter), прокрутка колесом, ползунок масштаба, инструмент
  «Правка текста» (кнопка нажимается, статус подсказывает шаг);
- **мерцание**: 14 кадров подряд во время непрерывного движения курсора по панели
  попиксельно совпали в полосе заголовка и панели — промежуточных «полупустых»
  кадров нет (двойная буферизация);
- сохранение поверх открытого файла: документ сначала освобождает файл, потом
  идёт подмена `.tmp` → `.pdf` и переоткрытие — `Ctrl+S` на копии демо-файла
  изменил файл (38 538 → 40 556 Б) и `pdftotext` читает его без ошибок;
- вид проверялся и без X-сервера: ключ `--shot` рендерит всё окно в BMP
  (заголовок, меню, панель инструментов, линейка, страница, строка состояния),
  по снимкам выравнивались метрики — `CAP_H 28`, `MENU_H 22`, `TB_H 34`,
  `RULER_H 22`, `STAT_H 22`, `RAIL_W 28`, `TOOLS_W 196`.
